# PersonalOS v4 长期架构与模块规范（候选）

## 结论
Obsidian 是唯一应用外壳；PersonalOS 是一个可单独停用的 TypeScript 插件；内容是独立 Markdown。

- **原生宿主拥有**：系统返回、工作区标签页、文档编辑、全局设置、搜索、外部链接权限。
- **PersonalOS 拥有**：记录类型筛选、速记草稿、记录列表、日记入口、后续经审核的独立功能视图。
- **Dropbox / Remotely Save 拥有**：同步任务及冲突处理。插件不重复实现云同步、不保管 OAuth 凭据。
- **GitHub + BRAT 拥有**：代码发行和更新，不保存个人数据。

## 文件结构
- `01 收集/记录/`：快速记录，独立生成文件，绝不修改已有同名文件。
- `10 日记/YYYY-MM-DD.md`：当日唯一，若已存在则仅打开，不覆盖。
- `20 笔记/`：知识/生活/工作/投资等普通 Markdown，以 YAML 分类属性区分。
- `90 系统/`：仅确有需要的维护说明和本地备份清单，不自动写布局日志。

原则：不强制搬移旧文件；不由插件自动删除文件或目录。备份在同步系统之外，恢复必须在独立临时目录演练。

## 独立功能模块接口（后续扩展）
新增模块必须满足以下契约：
1. 稳定 `moduleId`、独立的命令或 Obsidian `ItemView`；退出模块能回到宿主或记录列表。
2. 明确的数据写入路径；缺少权限或断网时，默认只读、可退出，不破坏其他数据。
3. 只采用 iOS 兼容的 Obsidian 公共 API。不得依赖 Electron、Node.js、shell 或私自注入系统工具栏。
4. GitHub 第三方开源项目仅在经过源码审计、移动端兼容性验证及许可证核查后集成；服务端开源项目不能直接安装到 iPhone 的 WebView 中，必须另外部署并通过经过许可的 API 接入。
5. 模块必须可单独停止使用；停止后 Markdown 内容仍可由原生 Obsidian 打开。
6. 禁止直接在手机端下载安装未审计的任意可执行脚本，不能承诺无限免费计算与云资源。

## UI/UX 发布要求
1. 无第二套固定底部/顶部导航；Obsidian 原生工具栏永远由宿主控制。
2. 从进入速记到可输入不超过两次点击；无网也能存草稿。
3. 退出速记不丢草稿；保存后自动回到记录列表。
4. 今日日记重复打开不重复创建、不覆盖。
5. 中文键盘弹出/收起、iPhone 安全区及原生返回必须真机验收。
6. 1k、10k 文件下，真实宿主性能和主线程响应需另测；Python/Chromium 容器基准不能代替 iOS 性能。
7. 错误状态要可见；不允许静默切换存储位置或假称“已经同步”。

## 5-10 年维护计划
- 每次提交：纯函数单测 + TypeScript 官方类型 + esbuild 构建 + 宿主回归。
- 每次候选发布：Chromium/WebKit 移动尺寸测试、真实 Obsidian 桌面、中文输入、切换回退。
- 每季度：备份恢复演练、旧插件 API 弃用检查、数据量和同步冲突检查。
- 每年：Markdown 可迁移性、依赖安全升级和跨版本恢复演练。

## 部署规则
`qa/**`、`feature/**` 独立测试，不能自动打 Release；只有用户审核验收通过，才允许合并 main 并发布正式版本。构建产物必须从官方 Obsidian TypeScript + esbuild 流程生成，禁止使用 QA 临时 `new Function` 打包器替代正式发行。
